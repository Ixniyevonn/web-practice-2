# Практическое задание 2: Интерактивная панель управления UI-компонентами

## Цель и подготовка

В первой работе вы добавляли действия одной странице. Теперь соберите панель из отдельных карточек-виджетов: их можно добавлять, сворачивать и удалять. Виджет — небольшой блок с собственной функцией, например список дел или погода.

Прочитайте лекции 4–7: классы, модули, внешние данные, формы и сохранение. Используйте нейросеть для получения кода по шагам. Технологии — HTML/CSS/обычный JS; классы и модули нужны, чтобы закрепить темы лекций.

Темы: панель путешественника, организатор студента, панель города, игровая статистика. Для простого старта возьмите панель путешественника: задачи, погода и курсы валют.

## Минимальный результат

- Три типа виджетов: список дел и два виджета с данными из двух разных внешних API.
- Добавление, сворачивание и удаление виджета; ошибка одной карточки не ломает остальные.
- В списке дел работают добавление, отметка выполнения и удаление.
- Сетевые карточки показывают загрузку, результат либо ошибку с кнопкой повтора.
- После обновления страницы восстанавливаются виджеты и задачи.
- Панель удобно выглядит на телефоне и компьютере.

## Порядок работы

1. Выберите тему. Попросите нейросеть создать каркас и оформление панели.
2. Получите базовый класс виджета и класс управления панелью.
3. Добавьте список дел; проверьте его до подключения сети.
4. Подключите два API отдельными запросами к нейросети.
5. Добавьте сохранение, обработку ошибок и мобильное оформление.
6. Проверьте, опубликуйте и отправьте ссылки.

API — способ получить данные другого сервиса, а не «нейросеть внутри сайта». Для погоды можно взять [Open-Meteo](https://open-meteo.com/en/docs), для валют — [Frankfurter](https://frankfurter.dev/). У Frankfurter сначала проверьте поддерживаемые валюты, например EUR/USD; наличие RUB не предполагается. Доступ API из вашей сети проверяйте браузером. Если источник недоступен, выберите другой с преподавателем.

Не помещайте секретные ключи в JS. Для обязательной работы выбирайте источники без секретного ключа. На случай отсутствия сети можно добавить явно подписанные демонстрационные данные, но два реальных запроса должны быть реализованы.

## Промпты для получения результата

### 1. Каркас и оформление

```text
Создай дашборд «Панель путешественника» на HTML/CSS/ванильном JavaScript.
Слева или сверху — кнопки добавления виджетов, в центре — сетка карточек.
Виджеты: задачи, погода, курсы валют. Стиль: [цвета/пример], аккуратные
карточки, единые кнопки, адаптация под телефон. Используй ES-модули.
Сначала выдай рабочий каркас с демонстрационными карточками и все файлы
целиком с именами. Без React, npm, сборки и платных библиотек.
```

### 2. Базовый класс виджета

```text
Для текущего проекта напиши класс UIComponent: конструктор принимает
id и title, render() создаёт DOM карточки, кнопки сворачивания и удаления.
Метод destroy() удаляет карточку и освобождает её обработчики/таймеры.
Используй export. Встрой класс в существующие файлы, сохрани дизайн.
Выдай полный код изменённых файлов, без пропусков.
```

### 3. Список дел

```text
Создай ToDoWidget, наследующий UIComponent. Внутри карточки: поле,
кнопка «Добавить», список, отметка выполнения и кнопка удаления задачи.
Пустые задачи не добавляй. Храни задачи в свойстве экземпляра, текст
вставляй через textContent. Сохрани общий стиль. Выдай полные файлы.
```

### 4. Управление панелью

```text
Создай класс Dashboard для нашей панели. addWidget(type) создаёт виджет
нужного типа и добавляет на страницу, removeWidget(id) вызывает destroy
и удаляет его из коллекции. Запрети повторное добавление одного типа,
покажи понятную подсказку. Подключи кнопки в main.js и импорты модулей.
Выдай полный рабочий код изменённых файлов.
```

### 5. Погода из API

```text
Добавь WeatherWidget с текущей погодой через Open-Meteo для [город].
Координаты [широта, долгота]. Используй fetch, проверку response.ok,
температуру, единицы измерения, загрузку, ошибку и кнопку «Повторить».
При удалении карточки отменяй запрос. API-ключ не нужен.
Сохрани архитектуру классов и дизайн. Выдай полные файлы.
```

### 6. Курсы валют из другого API

```text
Добавь CurrencyWidget с курсом EUR к USD через Frankfurter.
Вот актуальная документация/пример запроса [ссылка или фрагмент].
Покажи валюты, дату курса, загрузку и ошибку с повтором. Не придумывай
endpoint или поля: используй указанный пример. Этот виджет должен
работать независимо от погоды. Выдай полные изменённые файлы.
```

### 7. Сохранение и обработка отказов

```text
Добавь сохранение набора виджетов и задач в localStorage. После
обновления восстанови классы из сохранённых данных, а погоду и валюты
запроси заново. Повреждённый JSON и запрет сохранения не должны ломать
панель. При ошибке API покажи сообщение, а не вымышленные актуальные
данные. Выдай полные изменённые файлы. Текущий код: [код].
```

### 8. Внешний вид и проверка

```text
Вот моя панель [файлы/скриншот]. Улучши оформление в стиле [пример]:
сетка на компьютере, одна колонка на телефоне, читаемые числа, одинаковые
отступы и заметные действия. Не меняй API и логику. Затем проверь, что
после пяти удалений/добавлений один клик не запускает несколько действий.
Выдай полные изменённые файлы и короткий список действий для проверки.
```

Если запрос не работает, приложите точную ошибку Console, ответ API из Network и актуальный файл. Просите исправить один виджет с сохранением остальных.

## Что проверить и сдать

Добавьте все виджеты, сверните и удалите их, заполните список дел и обновите страницу. Проверьте оба API из своей сети. При выключенном интернете должна появиться ошибка и возможность повтора. Пять раз удалите и добавьте виджет — действие должно выполняться один раз.

Сдайте сайт и репозиторий. В коротком README укажите тему, запуск, два источника API, нейросеть и 2–3 полезных промпта.

**10 баллов:** управление виджетами и задачи — 2; два API и их ошибки — 3; классы/модули/сохранение — 2; дизайн и адаптивность — 1; публикация и демонстрация — 2.
